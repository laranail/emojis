# Status tags

78 status tags in six groups — `[OK]`, `[WARN]`, `[FAIL]`, `[SKIPPED]` — for logs, consoles and plain text,
each with the emoji it stands for. `Emojis::tags()` is the catalogue and `Mode::Tag` writes emoji as tags.

## Usage

```php
use Simtabi\Laranail\Emojis\Core\Enums\Mode;
use Simtabi\Laranail\Emojis\Facades\Emojis;

Emojis::text('✅ Deployed, ⚠️ 2 warnings')->to(Mode::Tag);  // "[OK] Deployed, [WARNING] 2 warnings"
Emojis::tags()->get('warn');                                 // Tag WARNING — label or alias, any case, [brackets] optional
Emojis::tags()->for('👍🏽');                                   // Tag YES — a toned emoji uses its base
Emojis::get('❌')->tag()?->role;                             // TagRole::Danger
Emojis::tags()->group('severity');                           // list<Tag>, in display order
Emojis::tags()->search('err');                               // label and alias matches, prefix first
```

| Method | Returns |
|---|---|
| `groups()` | group slug => label, in display order |
| `all()`, `group(string)` | `list<Tag>`; an unknown group gives `[]` |
| `get(string)` | the `Tag` with that label or alias, or `null` |
| `for(Emoji\|EmojiId\|string)` | the tag an emoji is written as, or `null` |
| `search(string, int $limit = 0)` | tags whose label or alias contains the term; 0 means no limit |

A `Tag` has `label`, `group`, `role` (a `TagRole`: `Success`, `Danger`, `Warning`, `Info`, `Muted`),
`symbol` (one character that is never an emoji, for plain-text output), `emoji` (primary first) and
`aliases`, plus `text(string $template = '[{tag}]')`.

## `Mode::Tag`

Only emoji that stand for a status have a tag; everything else degrades, to its name by default
(`🚀` → `[rocket]`). Change the chain with `degrade(Mode::Tag, …)` or `output.degradation.tag`, refuse with
`strict()`, and change the brackets with `output.tag_template` (it must contain `{tag}`).

Because it degrades to a localized name, `Mode::Tag` is not one of the ASCII-safe targets; chain it to
`Ascii` when the output must stay seven-bit. It is a target only: text holding `[OK]` is not read back as ✅.

## Why the labels are English

A tag is read by `grep`, log shippers and alert rules, which match `[ERROR]`, not its translation, so labels
are ASCII and English in every locale. The emoji names a tag degrades to are still localized.

## Where they come from

`database/sources/curated/tags.json`, collected from what tools already print: Symfony's `[OK]`, `[ERROR]`,
`[WARNING]`, `[NOTE]`, `[INFO]` and `[CAUTION]`, Laravel's `DONE`, `FAIL` and `SKIPPED`, Pest's `PASS`, `FAIL`
and `TODO`, and the eight PSR-3 log levels. The build fails on a duplicate label or alias, a symbol that is
an emoji, an unknown emoji, or an emoji mapped to two tags.

## Every tag

*Stands for* is the tag's emoji, primary first (`Tag::$emoji`). *Written for* is every emoji `Mode::Tag`
writes as the tag: its primary, plus curated extras. An emoji is written as one tag at most, so ✅ stands
for both OK and SUCCESS but is written `[OK]`. Generated by `.dev/tools/tags-doc.php`; `composer sync-check`
fails when it drifts from the dataset.
